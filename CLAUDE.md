# RoleCall — Build Instructions

RoleCall is a job-application tracker. This file governs how the app is built so it stays visually and structurally consistent. See `../rolecall_plan.md` for product context (why, user stories, features).

## Design system — follow it strictly
The design system lives in `design-system/`. Before building or restyling any UI, read `design-system/design-system.md`. The visual targets are `design-handoff/components/*.html` (open them in a browser) and `design-handoff/README.md` lists every change — **frozen references, not code: never import anything from `design-handoff/` or copy its markup.** Where the README's "Where the app differs" table disagrees with the HTML, the table wins.

- **Import `design-system/tokens.css` once, globally.** Reference its CSS variables for every color, font, spacing, radius, shadow, and z-index.
- **Never hardcode** a hex color, font size, spacing value, or radius. If a value you need isn't a token, add it to `tokens.css` first, then use it.
- **`tokens.css` has two layers, and components may only use the semantic one.** The raw palette (`--navy-*`, `--coral-*`, `--crimson-*`) exists to define the semantic layer (`--color-*`, `--sidebar-*`); a component referencing `--navy-200` directly is a bug even though it renders fine today. This split is what keeps a dark theme a token addition rather than a rewrite.
- **Spacing is the 4pt scale only** (`--space-*`) for layout. The Oct 21 tile specs are the stated exception — `design-system.md` writes their padding out literally (board card `12px 14px`, writing tile `9px 12px 9px 10px`, lane `3px 10px 12px`), so follow the spec there rather than rounding to the scale.
- **Text color** uses `--color-text` / `--color-text-heading` / `--color-text-secondary` / `--color-text-muted` (the floor for text). `--color-text-placeholder` is placeholders only; `--color-text-disabled` is non-text. **The sidebar is a dark ground with its own `--sidebar-*` text ramp** — never mix the two.
- **Four typefaces, one job each:** Nunito Sans 800 (`--font-display`) for page titles and the wordmark · Permanent Marker (`--font-accent`) for the ONE accent word in a page title, nothing else · Public Sans (`--font-sans`) for all UI chrome · Roboto (`--font-task`) for content the user wrote — task titles, notes, questions, board-card roles, writing. Use the `--text-*` role tokens, not ad-hoc font shorthands.
- **Coral comes in three strengths for accessibility — don't collapse them.** `--color-accent` / `--focus-ring` / `--color-title-accent` (brand `#e5482b`) are for non-text marks and the 25px/800 title accent word only; buttons fill `--color-primary`, links use `--color-link`. Brand coral fails AA as body text or behind white text. **Danger is crimson (`--color-danger`), never coral.**
- **Radius:** `--radius-sm` checkboxes/inputs/menu items · `--radius-md` nav items, search, cards, menus · `--radius-lg` task tiles, dialogs · **`--radius-full` for buttons, chips, status and priority pills, dots and avatars** — pills are the control shape (this reversed the Aug 2026 "no pill buttons" rule).
- **Reuse components** before building new ones — especially `Button.tsx`; don't re-declare button CSS in a screen's module.
- **Collections are tiles, in three weights.** Tasks and board cards: white `--radius-lg` tiles with `--shadow-task` (one `TaskRow` on Today and job detail). Notes and questions: *quiet* tiles — white, a faint lift, a `--color-bg-sunken` inset outline — lighter because they're reference, not action. Writing pieces: `--shadow-xs` tiles with a `--color-border-subtle` inset. Flat rows (divider + hover fill, 44px floor) remain only for contacts, menus and the data table. Cards are never page layout.
- **Avatars are people, never stages:** every avatar (account and contacts) uses `--avatar-bg` / `--avatar-text`. **Search matches** use `--highlight-bg` / `--highlight-text` and nothing else does. **Identifying icons** (writing type) are bare glyphs; **action icons** (copy, close) always sit in a filled control with a 44px hit area.
- **Priority is a rank, not a status.** Use the `--priority-*` navy tokens — never a pipeline color. Status colors belong to `statuses.json` and nothing else.

## Status / pipeline
- `design-system/statuses.json` is the **single source of truth** for pipeline status. It drives kanban columns, status badges, filters, and the database status enum.
- Store a job's status as its `id` in a **database ENUM column** whose allowed values are exactly the `id`s in `statuses.json`. Use `label` for display only; resolve `label`/`dot`/`badgeBg`/`badgeFg` in the UI from this file — never store them or re-pick status colors inline. Changing the pipeline means editing `statuses.json` **and** running an enum migration.
- Changing the pipeline = editing that one file.
- `design-system/task-statuses.json` (in progress / waiting / to do) and `design-system/priorities.json` (high / med / low) are the equivalent sources of truth for tasks. Same rule: DB enum of exactly those `id`s, edit-the-file-then-migrate. **The list order is Today's group order and nothing else** — In progress, Waiting, then To do: finish what you started, chase what is blocked, and the queue is the only group you can ignore today. Because order is presentation, the status a new task is born in is stated separately as **`$default`** in the same file, read by both `design_system.TASK_STATUS_DEFAULT` (the model default) and `defaultTaskStatusId`; re-ordering the groups must never quietly change what a new task is. Task **completion is a separate boolean**, not a status. Task status carries **no color** — colour on a task row belongs to the job's pipeline stage.

## Icons
- Use **Phosphor** (`@phosphor-icons/react`) per `design-system/icons.md`. **Never use emoji as icons.**
- Icon-only buttons need an `aria-label`; decorative icons are `aria-hidden`.

## Accessibility (non-negotiable)
- Keep the global `:focus-visible` ring on every interactive control — don't strip outlines.
- **44×44px is the floor on touch.** Controls with a transparent hit-area wrapper (checkbox, kebab, priority tag) stay 44px at every size. Buttons and menu items size from `--control-height` (36px on a fine pointer), which rises to 44px automatically under `@media (pointer: coarse)` — the one relaxation, and only where a mouse is driving.
- Native form elements (`<input>`, `<select>`, `<button>`) with associated labels.
- Design responsive — users are often on a phone. Two breakpoints carry the app: **900px** (sidebar → drawer) and **600px** (row reflow).
- Wrap animation in `@media (prefers-reduced-motion: reduce)`.

## Conventions
- **Comment every functional unit.** In all code files, put a concise comment above each function, component, class, or self-contained block explaining what it does, so the code reads top-to-bottom without deciphering it. Say what and why, not a restatement of the syntax; keep it to a line or two.
- Nav vocabulary: **Today · Jobs · Writing Library · Ratings** — match routes to these labels (`/ratings` is a placeholder page until the ratings chart is built). The old export's Board/Table/Archive/Contacts wording is superseded; don't reintroduce it.
- **Closed jobs are a filter under Jobs**, not a top-level destination — there is no Archive nav item. Writing Library is a different thing entirely: the reusable pool of cover letters, blurbs and impact statements (see story 3 in `../rolecall_plan.md`).
- When a change lands, keep this file and `design-system/` as the source of truth — fold new decisions back in rather than letting components drift.

## Stack & architecture (settled)
- **Frontend:** Vite + React + TypeScript in `frontend/` (strict tsconfig: `verbatimModuleSyntax`, `erasableSyntaxOnly`, no unused locals — use `import type`, no enums). Styling is **CSS Modules over `tokens.css`**; there is no component library.
- **Backend:** Django 6 + Django REST Framework in `backend/` (project `config`, app `tracker`), SQLite (`backend/db.sqlite3`, gitignored). API under `/api/` (`jobs`, `tasks`, `notes`, `questions`, `contacts`, `writing`, `meta`).
- **Python** lives in the repo-root **`.venv/`** (Python 3.14, machine-wide install). Always use `.venv/Scripts/python.exe`; the bare `python` command is a Windows Store stub and won't work.
- **Enums are generated from the JSON, never hardcoded.** `backend/tracker/design_system.py` loads `design-system/*.json` to build model `choices` **and** DB `CheckConstraint`s. Editing a JSON file changes the constraint → `makemigrations` produces the migration. This is the enforcement mechanism behind the "edit the file, then migrate" rule.
- **Frontend resolvers** in `frontend/src/design-system/*.ts` import the same JSON so labels/colours resolve from one source of truth. Vite `server.fs.allow` includes the repo root so the frontend can import `../../design-system/`.

## Data model (see `backend/tracker/models.py`)
- **Job** (role, company [default "undisclosed"], applied_on, posting_url, status, fit_score, created_at). **`fit_score`** (0–10 to one decimal, null = unrated) is a column of its own rather than a line inside a note, so jobs can be ranked by it later without parsing "~8.5/10" out of prose; a DB check constraint backs the range. The **reasoning** behind a score is a note like any other judgement — `description_summary` and `fit_notes` were added and then removed (migrations `0002`/`0003`) once the job page proved notes already carry that. A separate **job priority** is still owed (stories 4–6) and overlaps `fit_score` — settle whether they are one field before adding it. · **Task** (job FK `SET_NULL`, title, category, status, is_done, priority, due_on, created_at) · **Note**/**Question** (attached to exactly one of a job or task) · **Contact** (M2M → jobs) · **WritingPiece** (job FK `SET_NULL`, type, title, body [markdown], `derived_from` FK to self, created_at, **updated_at** — the only `auto_now` in the app) / **WritingPassage** (piece FK `CASCADE`, text, position, use_count, last_used_at).
- **Task job/category is "never both"** (not "exactly one"): a task may briefly have neither after its job is deleted (`SET_NULL`). Completion is the `is_done` boolean, never a status.
- **Auth is deferred:** no `user` FK yet; adding it later is an additive migration. DRF runs open (no auth class, `AllowAny`) for the single-user MVP — lock down when auth lands.

## App shell (built)
- **Global top bar** (`components/TopBar.tsx`, `--topbar-height`, `--topbar-bg`, sticky at every width): the ⌘K search field left, **New application** (primary, `md`) and the account avatar right. **Global actions live here; page actions stay in each screen's Toolbar** — that split is why the bar exists. The **⌘K field is rendered disabled** (`aria-disabled`, "Search is coming soon", `cursor: not-allowed`) until the palette is designed, and **hidden below 600px**: a disabled control is the first thing that should give up phone width. The **avatar is a `<span>`, not a button** — there is no account menu to open yet, and this pass's firmest rule is that nothing may look clickable and do nothing.
- **The content is a page sheet.** `AppShell`'s pane carries `--topbar-bg`; `.page` inside it is `--color-bg` with a `--page-corner-radius` top-left corner and a 1px inset hairline, so the dark rail and the pale bar **frame** the sheet. The sticky Toolbar repeats that corner — an opaque bar at the top of the sheet would otherwise square it off. Below 900px the sidebar leaves the grid, so the corner goes with it.
- **Left sidebar** (`components/Sidebar.tsx`, 240px, the dark `--sidebar-bg` navy rail with its own `--sidebar-*` text ramp): Nunito Sans wordmark · nav (Today · Jobs · Writing Library · **Ratings**, each with its Phosphor icon at `--nav-icon-size`; active item is a pale pill at weight 800) · a `Pipeline` section of active stages with live counts linking to `/jobs?status=<id>`. **No account slot** — it moved to the top bar, so the rail is navigation and nothing else. Collapses to an overlay drawer below 900px.
- **`components/AppShell.tsx`** owns the frame and mounts `useTracker()` — one fetch feeds both the sidebar counts and the Today list. Screens render into its `Outlet` and read data via `useTrackerContext()`.
- **`components/Toolbar.tsx`** is the sticky per-screen header (under the top bar) and **owns the page title** — screens don't render their own `<h1>`. An optional `accent` prop sets **one** word of the title upright in `--font-accent` (Permanent Marker, weight 400, `--color-title-accent`); an optional `eyebrow` stacks a qualifying line above the title and switches it from ellipsising to **wrapping**, which is how the job page gets its company + stage line. The `backTo` affordance is a white 40px disc inside a 44px target. **Below 600px** the actions wrap to their own row and the bar stops being sticky — two rows are too tall to pin over a phone — so Today's sticky group headers re-anchor to `--topbar-height` there.
- **New application is an app-level action**, so it lives in the top bar, not in any screen's toolbar. The shell owns the `JobForm` dialog and still hands screens `onNewApplication()` on the context (empty states use it) alongside `onOpenNav()`. Saving navigates to `/jobs?status=<id>` — the board is the only place the job is visible — replacing the history entry when already on Jobs and pushing from anywhere else, so Back returns you to where you were.
- **Routes:** `/` Today · `/jobs` · `/jobs/:id` · `/writing` · `/writing/:id` · `/ratings` (react-router). `/ratings` is `routes/Ratings.tsx`, an `EmptyState` placeholder with no CTA until the chart is designed.

## Today screen (built)
- Page title **"Step *forward*"** (Nunito Sans 800, with `forward` in the Permanent Marker accent face). **The pipeline band is gone** — the sidebar's Pipeline section carries the same stage counts permanently and on every screen, so repeating them here only pushed the work down the page. `PipelineBand` is deleted; the `--text-band-*` and `--pipeline-segment-*` tokens stay unused.
- **The list's controls live in the Toolbar**, not over the list: **New task** (secondary, `lg`) and the **Show completed** toggle. Nothing sits between the page title and the first group, so `TodayList` has no header of its own. `Today.tsx` therefore owns the `showCompleted` preference and the `TaskForm` dialog, and hands `TodayList` the preference plus `onNewTask`/`onEditTask`; the list keeps the grouping and the drag.
- Rows render **checkbox · title · chip · priority · row menu** as a **floating task tile** (`--shadow-task`, `--radius-lg`, 3px apart; done tiles trade the lift for `--shadow-done`) — no dates (`due_on` is stored but not displayed), no waiting day-count. **Open task titles all use `--color-text`** — a job-less task is not differentiated by text colour. Done tasks go `--color-text-muted` and strike through in place, keeping their weight (chips mute too) and **keep their position** — checking a row off never makes it move. The row menu (kebab) holds **Edit** — which opens the task dialog on that row, the one place every field of a task is edited — and **Delete task**. There is no inline rename: a row-local editor that reaches one field of six is a second, weaker form. Delete is behind the menu (no separate confirm dialog yet).
- Groups by task-status order under an eyebrow header carrying a count; sorts by **priority rank alone**. **A row moves between statuses by dragging it into another group** (same optimistic PATCH + snap-back as the Jobs board, and the same deferred `dragstart` so Chrome doesn't cancel the drag). Empty groups are hidden at rest but **all appear while a drag is in flight** — a group you can't see is a group you can't drop into, and moving the last task out of a status would otherwise strand it. Drag is never the only route: the menu's **Edit** opens the dialog with its Status select, which is the keyboard and touch path to the same change. Completion is deliberately not a sort key: a row that jumps the moment you check it pulls itself out from under the cursor. The sort is stable, so tasks at equal rank hold the API's newest-first order.
- **`TaskForm` both creates and edits** (`components/TaskForm.tsx`, composed from `Dialog.tsx` + `Form.module.css`) — same fields, same rules, only the verb differs, exactly as `JobForm` does for jobs. It covers every field a task has: title · job · category · status · priority · due date. **`is_done` appears only when editing** — a task you're creating isn't done, so there is nothing to switch; an existing one has a state worth correcting from here as well as from the row's checkbox. The Toolbar's **New task**, the empty-state CTA and a row menu's **Edit** all open it, and it is **mounted only while open** so a new task starts empty and an edit starts from the row it was opened on.
  - **Job and category are mutually exclusive** in the form as in the model: picking a job disables the category select and clears it, so "never both" can't be violated from the UI. Blank due date sends `null`.
  - Saving POSTs and prepends the row. Create is **not optimistic** — the row needs the server's id, and the chip needs the company/stage the server resolves from the FK — so the dialog stays open on failure with the typing intact. **An edit is awaited too, for the same reason**: the saved record is merged back whole (`onUpdateTask`), because re-pointing a task at another job changes the `job_company`/`job_status` chip that the patch itself never mentions. The row's own edits — checkbox, priority pill, a drag between groups — stay optimistic with revert-on-failure, since they have nowhere to show a failure.
- **A `Show completed` toggle** (`components/Toggle.tsx`) in the **Toolbar** hides done tasks from every group; groups that empty out drop away, and the toggle only appears once something is actually done. It **persists across sessions** via `usePersistedBoolean` (`localStorage`, `rolecall.` prefix, every access guarded because blocked storage throws rather than returning null) — how the list should read is a standing preference, not something to re-decide every visit. It stays a view preference, not a database column.
- Two empty states, with different words: nothing tracked yet (invites the first task) and everything done with the completed rows hidden (points back at the toggle).
- Loading renders skeleton rows; the error state is a card with a working **Try again** wired to `reload()`.

## Jobs screen (built)
- **A kanban board** (`components/JobBoard.tsx` + `JobCard.tsx`): one **tinted lane** per **active** stage in `statuses.json`, all five on screen at once. Title is **"Jobs in *progress*"**; there is no page action, since New application is global and sits in the top bar.
- **Each lane carries its own stage colour**: the stage's `badgeBg` mixed 25% into the page sheet (`color-mix`), outlined with the same mix at 55%, `--radius-lg`. `laneColors()` hands `badgeBg`/`badgeFg`/`dot` to CSS as `--sb`/`--sf`/`--sd` custom properties, so **no stage colour is ever written in a stylesheet**. The tint is what keeps the board reading as a pipeline once the lanes stack on a phone and the headers scroll apart. Header: the stage name in its own `badgeFg`, 600 14px, sentence case, **no dot**, with a white count pill. An empty stage keeps its full lane behind a dashed outline in the stage's dot colour reading **"Nothing here yet"**.
- **No horizontal scroll ever** — lanes are `flex: 1 1 0` and share the pane; `--board-column-min` is only the wrap floor. Wraps below 900px, one lane per row below 600px.
- **Cards are fixed at 112px** so lanes line up: **company eyebrow → role (Roboto, 2-line clamp) → a status line pinned to the bottom** reading `Applied Jul 7` when `applied_on` is set and `Started Jul 14` from `created_at` otherwise — always one line, which is what the fixed height needs. **No stage pill and no dot on the card**: the lane's tint carries the stage, and five copies of one fact inside one lane is noise. A visually-hidden span carries the stage name on each card, since the tint reaches only the eye.
- **The whole card opens `/jobs/:id`**, via a link stretched across it (`inset: 0`) rather than a click handler, so middle-click and copy-link still work; the **role is its own link to `posting_url`**, raised above that layer. The card is still the drag handle, and a click synthesised at the end of a drag is swallowed.
- **Stage changes by drag here, or from the job page's stage pill** — dropping the card's pill removed the board's own non-drag path, which is why the job page's inline pill is now the only keyboard and touch route to a stage change.
- **`?status=<id>` focuses a lane** (accent ring replacing its faint outline), it does not filter to one — hiding the other stages would defeat the board. The sidebar's Pipeline links land here.
- **New application** (`components/JobForm.tsx`, composed from `Dialog.tsx` + `Form.module.css`) covers every field a job is born with: role · company · stage · applied date · posting link. The top bar's button and the empty-state CTA open the shell's one dialog; it is **mounted only while open** so each visit starts empty.
  - **Stage offers active stages only** and defaults to the focused lane, else the pipeline's first stage — creating straight into a closed stage would save a job with nowhere to appear. Blank **company omits the field** so the model's `undisclosed` default applies (an empty string is a 400). A posting link with no scheme gains `https://` on blur; **applied date is capped at today**.
  - Saving POSTs, adds the card, then focuses the lane it landed in via `?status=`. Create is **not optimistic** — the card needs the server's id — so the dialog stays open on failure with the typing intact.
- **Closed stages have no lane and no surface yet** — a closed-jobs filter is still owed.
- Loading uses `SkeletonBoard`; the error state and `.srOnly` compose from `routes/Pane.module.css` rather than being restated.

## Job detail screen (built)
- **`/jobs/:id` is the per-job workspace** (`routes/JobDetail.tsx`): where one application stands and what's outstanding on it. Today is the cross-job "what do I do now"; this page is "what's the state of this one". Reached by clicking a card on the board.
- **The header IS the Toolbar.** The white round `backTo` disc, then the **company + stage eyebrow** (`components/JobHeader.tsx`, passed as the Toolbar's `eyebrow`) stacked above the **role as a wrapping title**, with **Edit details** (secondary, `lg`) in the actions slot. `JobHeader` is no longer a block in the page body. Stage stays inline in that eyebrow because it is the page's most frequent edit by a distance — and, since the board's cards lost their pill, the only keyboard and touch route to a stage change. The eyebrow line is 44px tall: the pill's hit area is not negotiable, and a header has room for it.
- **The page is split by KIND of information, and that split is the design.** A **main column** holds the work you act on; a **sticky 300px rail** (`--detail-rail-width`, blocks `--space-5` apart) holds reference you only read. Its first version was one column of four identical-looking sections and read as scattered — the fix was structural, not cosmetic.
- **Every section title is an eyebrow now** (`--text-eyebrow`, uppercase), main and rail alike. The page's hierarchy is carried by the 25px Toolbar title alone; four 16px headings under it read as four competing pages rather than one page's parts. Rail blocks sit on `--color-bg-sunken` — **not cards**, which are never page layout.
- **Order is header → Tasks → Notes → Questions**, then the rail. Tasks are what you act on; the log has the traffic once a job is live, and a question is usually raised by something just logged. **No count badges anywhere** — section headers are labels, not a dashboard.
- **Each list keeps a distinct leading mark**, which is what lets the eye tell them apart at a glance: tasks = the 44px checkbox · notes = a 38px **date square** (month over day, `--color-bg-sunken`) · questions = a 38px **"?" square** in `--question-mark-bg`/`-text`, a `✓` once resolved. The question mark owns those tokens rather than borrowing Intro's teal: pipeline colour is the only colour allowed to carry meaning, and a question is not a stage.
- **Tasks are tiles exactly as on Today** (the same `TaskRow`, `showChip={false}`). **Notes and questions are *quiet* tiles** — white, `--radius-lg`, `--shadow-xs` plus a `--color-bg-sunken` inset outline, Roboto 400 15px in `--color-text-secondary`, `--task-gap` apart — deliberately lighter than a task tile, because they are reference rather than action. A question also shows **"Asked Jul 13"** under its text, which is where its date goes since the "?" owns the square.
- **Rail — `JobFacts.tsx`**: a real `<dl>` of Applied (**or "Not applied yet"**, a real state) · Added · Fit (**or "Not rated"**) · Posting, the row omitted when there's no URL.
- **Rail — `ContactList.tsx`**: **navy avatar** (`--avatar-*`, the same tokens as the account avatar — a person isn't at a pipeline stage, and white-on-stage-colour failed contrast) + name + what they are, the row itself opening the editor. A row's **hover lifts to `--color-surface`**, because `--color-surface-active` is the same value as `--color-bg-sunken` and so is invisible on the rail block. **`ContactForm.tsx`** creates someone new *or links a person who already exists on another job* — one person, several applications. **Every contact write sends the COMPLETE `jobs` list**: the M2M is declared on `Contact`, so it's only writable from that side and the API *replaces* the list — a partial one silently detaches them from their other jobs. **Removing** unlinks from this job; if it was their last, the contact is deleted, since an unlinked person has no surface anywhere. Note the model has **no per-job role** — "Recruiter" describes the person, not the person on this job.
- **Adding is a button, not a live field.** Each section's header carries **+ Add**; `InlineAdd.tsx` opens under it for notes and questions, and tasks open the shared **`TaskForm`** dialog with `initialJobId` set. The composer stays open after a save (clears and refocuses) so several notes can be logged in a row; Escape or Cancel closes it.
- **Notes edit in place.** A pencil sits beside the delete (both revealed on hover or focus, always visible under `pointer: coarse`), opening the entry in a field shaped like the composer that wrote it: Escape abandons, ⌘/Ctrl+Enter saves, and saving an unchanged note skips the PATCH. Awaited rather than optimistic, so a failure keeps the editor open with the typing intact. **The date stays `created_at`** — editing corrects the record of what happened, it doesn't re-file the entry under today. There is no `updated_at`, so an edit leaves no trace; add the column if that ever matters.
- **Questions:** open first, resolved folded behind **Show resolved**. **Answering *is* resolving** — `answer` and `resolved_at` are one PATCH, so a question can't sit answered-but-open. Reopening clears the stamp and keeps the answer.
- **State split:** `useJobDetail(id)` owns the detail payload (fit, contacts, notes, questions) and PATCHes what only this page can see; the **shell owns the board-visible fields** (role, company, stage, dates) so the board and sidebar counts follow, and the page mirrors the **saved** record back into its copy (the API normalises — a cleared company returns as `undisclosed`).
- `GET /api/jobs/:id/` **embeds contacts, notes and questions** so the page loads in one request; the board's list payload stays slim. A **404 is its own state** ("No such application"), separate from the server-unreachable error.
- **Below 900px** the rail stacks under the main column. DOM order is main→rail at every width, so tab order always matches reading order.
- **Still owed here:** the **writing drawer** (which should now compose `Drawer.tsx`, the same shell the Writing Library's piece panel uses), and a **confirm step for deleting** a note or question (they delete optimistically, matching tasks).

## Writing Library (built)
- **`/writing` is the reusable pool** of resumes, cover letters, blurbs and impact statements (story 3). Title **"*Ready* when you are"**. **One screen, not two**: a piece opens as a **side panel over the dimmed library** rather than as its own page, so the list you were choosing from stays in view. `/writing/:id` renders the same route with that panel open, which is what keeps a link to a piece working — `routes/WritingPiece.tsx` is gone.
- **Read and copy only.** Nothing here creates, edits or deletes a piece — the API is a `ReadOnlyModelViewSet` and says so. **Writing is authored on a job page** (still to build), which is what keeps the library *a view over the data* rather than a second place to remember to populate. Until that lands, content arrives via `seed_writing` or the Django admin.
- **Top row: the query and two filters, as equals** — all three 48px, white, `--radius-lg`, `--shadow-search`, no border. `SearchField.tsx` takes the width; **Any company** and **Any time** are `FilterMenu.tsx` (button + popover, dismissed by Escape or an outside click, focus returned to the trigger). A native `<select>` can't be given that height, radius and shadow across browsers, which is why they're popovers. Below 760px the query takes a row of its own rather than being squeezed — it's the control the screen exists for.
- **"Any time" is a server-side window in days** (`?since=30|90|365`), applied by both `WritingPieceViewSet.get_queryset` and `search_passages`. It has to be server-side: a passage hit carries no date, so a client-side comparison could not narrow the two modes identically.
- **Type pills** below: *All writing · Impact statements · Blurbs · Cover letters · Resumes*, each a glyph + label at `--control-height-sm`, `--radius-full`, white with a 1px inset. **Active is a solid `--priority-high-bg` fill** — selection reads as fill and weight, never hue, because writing types carry no colour. Plurals are derived from the JSON label, not a second place labels live. Search adds a count line ("5 lines across 5 pieces").
- **One tile language for both modes**, 12px apart, `--shadow-xs` plus a `--color-border-subtle` inset. Left to right: the type's **bare glyph** · the body, **content first** (the preview, then the quiet title line of type eyebrow · title · company) · the date (browse only) · **copy**. **The icon rule**: identifying icons (writing type) are bare glyphs with no box and no hover; action icons (copy, close) always sit in a filled control.
- **Every 32px action button sits inside a transparent 44px hit area.** `CopyButton` is a 44px button wrapping a 32px face — `tile` (filled `--color-bg-sunken`, warming to `--color-primary` on hover) and `paragraph` (quiet until its block is hovered). The paragraph variant's reveal is driven by a `--copy-reveal` custom property the containing block sets, because a `.para:hover .face` selector cannot cross two CSS Module files; under `pointer: coarse` it is always visible.
- **The row unit flips on the query.** No query lists **pieces**, previewed by their opening passage clamped to two lines; a query lists **passages**, showing the matched line in full — it is the answer, not a teaser. **Filters narrow documents, search returns lines**, and type/company/time apply server-side in both so the two modes narrow by identical rules.
- **The index payload carries a `preview`** — the piece's first passage, added to `WritingPieceSerializer` because a tile leads with content. One passage rather than the body keeps the list slim (the whole point of that serializer); the view prefetches `passages` so it costs no query per row.
- **`components/Drawer.tsx` is the general right-docked panel** — scrim, focus trap, Escape, focus return, frozen body scroll, portal to `<body>`: deliberately the same behaviour as `Dialog.tsx`. The difference is that the **caller owns the whole inside**, header and close button included, because a drawer's header varies where a dialog's doesn't. The job page's writing drawer is meant to reuse it.
- **The open piece** (`components/WritingPiecePanel.tsx`, `min(560px, 100%)`): type glyph · type eyebrow over a one-line title · quick-copy · close; a meta row of company · "Updated Jul 6" · **"Copied N×"** (the sum of the piece's passage `use_count`, omitted at 0 — the app tracks copies, not which applications a piece went into, so the design's "Used in 1 application" is a number we can't stand behind); then the full text, one block per passage, each copyable. The opened tile takes a **2px `--color-accent` ring** so the list still shows where the panel came from.
- **Copy is the primary action, not open.** A successful clipboard write increments `use_count` and stamps `last_used_at` — which is how **"best writing" is computed rather than starred**. The panel's **quick-copy increments nothing**: crediting every passage for one bulk copy would inflate the signal "most used" depends on.
- **Passages are derived, never authored.** `passages.py` splits `body` on blank lines and list items (headings dropped) and `WritingPiece.save()` re-derives on every save — **the only `save()` override in the app**, so the admin and the seed command chunk identically. It **preserves `use_count` by matching text**: unchanged passages keep their row and their counts; a reworded one starts again. `body` being real markdown is load-bearing — one unstructured blob becomes one useless passage, one useless tile preview, and topic search quietly stops working.
- **Search is SQLite FTS5** (`search.py` + migration `0006`, the only hand-written SQL in the repo): an external-content virtual table over `writing_passage`, kept in sync by DB triggers so every write path — ORM, admin, bulk delete — indexes for free. `porter` tokenizer, so "fundraiser" finds "fundraising". `snippet()` returns the excerpt.
- **Raw input must never reach FTS5.** `team's`, `donor OR` and `"unclosed` are each a syntax error and would be a 500. `to_match_query()` reduces the input to quoted word runs with a `*` on the last (so it narrows as you type). The cost: **boolean operators are treated as literal words**, which is right for a search box.
- **Excerpt highlighting uses control-character sentinels** (STX/ETX from `chr(2)`/`String.fromCharCode(2)`), not brackets or markup, so a passage containing `[` or `<b>` can't corrupt it and `Excerpt.tsx` renders `<mark>` by splitting text nodes — nothing is ever interpreted as HTML. The mark is **highlighter yellow** (`--highlight-bg`/`-text`), with no weight change: yellow is reserved for "found here", and bolding on top of the fill makes a line jump rather than scan.
- **Search results are capped at 50** rather than paginated: no other endpoint in this API has an envelope, and search shouldn't be the one that does.
- Filters live in the URL (`?q=&type=&company=&since=&sort=`) like the board's `?status=`; the query is **debounced 200ms** (`useDebounced`) because this is the first screen whose narrowing is a server round-trip.
- State is in route-local hooks (`useWritingLibrary`, `useWritingPiece`), not the shell: nothing outside `/writing` reads pieces, and the panel needs a **`missing`** state the shell's `LoadState` doesn't have. `useWritingPiece(null)` is the no-piece-open case — the hook still runs, as hooks must, and simply holds nothing.
- **The index's empty state carries no CTA** — a deliberate exception to the design system's rule, because there is genuinely no next step in-app until job-page authoring exists, and a button that opens nothing is worse than none.
- **The visible sort control is gone**, replaced by the time filter: the Oct 21 design's top row is two buttons, and the default orders (recency when browsing, relevance when searching) are what it specifies. `?sort=used` still works end-to-end in the API and the hook, so **"most used" is one control away** if it turns out to be missed — settle that before building anything else here.
- **Still owed:** authoring on the job page (and with it the pull drawer, which should compose `Drawer.tsx`), plus `Duplicate & tailor` — `derived_from` is populated but nothing forks a piece yet, and **lineage is no longer displayed anywhere** since the piece page became a panel; put it back in the panel's meta row if it is wanted.

## Running the app
- **Seed** (real data, gitignored): `.venv/Scripts/python.exe backend/manage.py seed_local` (reads `seed.local.json`; wipe-and-reload).
- **Seed writing** (separate on purpose): `.venv/Scripts/python.exe backend/manage.py seed_writing` (reads `writing.seed.local.json`; wipe-and-reload **within the writing tables only** — it never touches jobs, tasks, notes, questions or contacts). Pieces name their job by **company + role together**, since company alone is ambiguous; a miss leaves the piece unattached and warns rather than failing the load. Passages are not in the file — they are derived from `body`. See `writing.seed.local.example.json` for the shape.
- **Backend:** `.venv/Scripts/python.exe backend/manage.py runserver 8000`
- **Frontend:** `cd frontend && npm run dev` (serves `:5173`, calls the API at `localhost:8000`).
- **npm needs the system CA:** this machine intercepts TLS, so npm install/create must run with `NODE_OPTIONS=--use-system-ca` (don't disable strict-ssl). Not needed once deps are installed.
